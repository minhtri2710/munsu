## Decision gates (Human — resolve before the dependent slice runs)

* **G1 — ADR-0004 §9 ContextManifest (resolved 2026-09-03):** the owner chose retire (won't-build). [ADR-0023](../adr/0023-retire-unbuilt-lifecycle-and-recovery-machinery.md) records the retirement; soldiers receive launch context through the charter + SHA-verified launch-artifact manifest, not a §9 bounded-context budget. No aggregate field, store, or CLI carries a context manifest.
* **G2 — ADR-0004 §7 DispatchInterpretation (resolved 2026-09-03):** the owner chose subsumed. [ADR-0023](../adr/0023-retire-unbuilt-lifecycle-and-recovery-machinery.md) records it: directive/ready-set divergence is gated by a durable `DispatchHold` (`Reason`/`Scope`/`Actions`) and delivery authority is a head-bound `DeliveryAuthorization`; no distinct interpretation record is built.
* **G3 — ADR-0005 §6 Git fencing:** the wrapper exists but as a *pretool-check hook* (unhooked harnesses are unfenced) and the §6 6-tier capability ladder was collapsed to a flat Ship allowlist by #414B. Ratify the flat allowlist as the owner-clean target (mark the ladder superseded), or treat the tier model / harness-agnostic enforcement as real work. Security-adjacent → hard gate.
* **G4 — ADR-0003 §10 env-override boundary (resolved 2026-09-03):** the owner chose delete over wire. The dormant (always-empty) `BoundaryOverrides` plumbing was removed from `config.ResolveProject`/`ProjectDigest`/`NewResolvedSnapshot` and `fleet.ResolveProjectSnapshot`; resolution is now the two typed layers `base ⨂ project overlay`. ADR-0003 §3/§4/§10 record the retirement. The `MUNSU_*_OVERRIDE` env-var names were never read by production code (only cleared in test isolation and asserted-ignored by `TestConfigGetIgnoresEnvOverride`).
* **G5 — ADR-0008 §13 delivery shape (RESOLVED in T0):** §13 previously mandated "one coherent cutover on one branch… no supported phases," but the program was delivered incrementally (gate-per-issue, #402–#418). Amended in T0 to record incremental delivery as the accepted shape; see ADR-0008 §13.

### T2 — Config CLI completion (ADR-0003, small build; after T0)
* **C1** — Wire `munsu project config get/set` and `munsu captain config get/set` to the existing (currently CLI-unreachable) `StoreProjectOverlay`/`LoadProjectOverlay` + captain profile store. **Validation:** round-trip test; overlay reflected in resolved snapshot.
* **C2 (landed 2026-09-04 — scope reshaped by research):** the original sketch ("consolidate `soldier-harness`, `model`, `model-allowlist`, `wake-delivery-mode`, `afk-*` onto `base.json`; retire `config.Get/Set`") did not survive a reader-home trace. Only the three **launch-profile** keys — `soldier-harness`, `model`, `captain-harness` — carry fleet-base semantics and were consolidated onto `config/base.json`: authored by `config set` (`setBaseConfigField`/`setCaptainProfileInBase`), read by `Soldier`/`CaptainProfileFromHome`, with no flat file written or read (the `"default"`/empty sentinel normalizes to unset at the write boundary). The motivating defect: `config set soldier-harness`/`model` previously wrote flat-only while `init` and the published snapshot used `base.json`, so a `set` was shadowed and captains received the stale init-time value. The other keys **stay flat by explicit decision** — they are home-local with no fleet-base semantics: `wake-delivery-mode` (`ResolveWakeDeliveryMode`) runs in captain homes, which carry no `base.json`; `afk-*` are General-only home-daemon tuning (`loadAfkConfig`), not per-project overlay fields; `model-allowlist` is a policy file with its own loader (`LoadModelAllowlist`) and `PolicyHome` redirect; and the bootstrap-identity keys `parent-home`/`install-root` were always flat. `config.Get`/`config.Set` therefore survive for the home-local/policy keys; the retirement narrowed to the launch-profile keys. Touched `internal/cli` (`config_cmd.go`, `init.go`, `harness_cmd.go`), `internal/harness` (`harness.go`: deleted `lookupConfig`/`fillCaptainModelFallback`), `internal/bootstrap`, `internal/fleet` (`captain_recover.go` diagnostic). **Validation:** full `go build/vet/test ./...` green; deadcode lane clean; per-key table in the PR body. ADR-0003 status header records the consolidation.
