General's typed Captain-health observation remains separate from the fleet-owned recovery workflow, which intentionally reads and mutates Captain-home state. The remaining engineering is therefore small: gate G3 (ADR-0005 §6 Git fencing, security-adjacent) only. ADR-0005 §5 (General→Captain relay was never built; the running status-signal model — typed-status probing via `checkAliveWithProbe`, watcher status handled separately, recovery via General-scoped `RecoverTransaction`) and ADR-0008 §2 (`.meta`/`.status` retained as home-owned projections, never read by `taskauthority`) were reconciled to the running contract 2026-09-04 rather than built out. The Captain-profile CLI half was retired by owner decision C1(B) on 2026-09-04 rather than built. G1 (ADR-0004 §9 ContextManifest, retired) and G2 (ADR-0004 §7 DispatchInterpretation, subsumed) are likewise resolved by ADR-0023; G4 (BoundaryOverrides) shipped as #744.

## Decision gates (Human — resolve before the dependent slice runs)

* **G1 — ADR-0004 §9 ContextManifest (resolved 2026-09-03):** the owner chose retire (won't-build). [ADR-0023](../adr/0023-retire-unbuilt-lifecycle-and-recovery-machinery.md) records the retirement; soldiers receive launch context through the charter + SHA-verified launch-artifact manifest, not a §9 bounded-context budget. No aggregate field, store, or CLI carries a context manifest.
* **G2 — ADR-0004 §7 DispatchInterpretation (resolved 2026-09-03):** the owner chose subsumed. [ADR-0023](../adr/0023-retire-unbuilt-lifecycle-and-recovery-machinery.md) records it: directive/ready-set divergence is gated by a durable `DispatchHold` (`Reason`/`Scope`/`Actions`) and delivery authority is a head-bound `DeliveryAuthorization`; no distinct interpretation record is built.
* **G3 — ADR-0005 §6 Git fencing:** the wrapper exists but as a *pretool-check hook* (unhooked harnesses are unfenced) and the §6 6-tier capability ladder was collapsed to a flat Ship allowlist by #414B. Ratify the flat allowlist as the owner-clean target (mark the ladder superseded), or treat the tier model / harness-agnostic enforcement as real work. Security-adjacent → hard gate.
* **G4 — ADR-0003 §10 env-override boundary (resolved 2026-09-03):** the owner chose delete over wire. The dormant (always-empty) `BoundaryOverrides` plumbing was removed from `config.ResolveProject`/`ProjectDigest`/`NewResolvedSnapshot` and `fleet.ResolveProjectSnapshot`; resolution is now the two typed layers `base ⨂ project overlay`. ADR-0003 §3/§4/§10 record the retirement. The `MUNSU_*_OVERRIDE` env-var names were never read by production code (only cleared in test isolation and asserted-ignored by `TestConfigGetIgnoresEnvOverride`).
* **G5 — ADR-0008 §13 delivery shape (RESOLVED in T0):** §13 previously mandated "one coherent cutover on one branch… no supported phases," but the program was delivered incrementally (gate-per-issue, #402–#418). Amended in T0 to record incremental delivery as the accepted shape; see ADR-0008 §13.

* **S4** — RECONCILED (2026-09-04, ADR-0005 §5). The General→Captain `WatcherLease` observation+recovery-request relay was never built. `WatcherLease` is a purely intra-home single-writer lock: same-home lease lifecycle fencing reads it through `ClaimWatcherLease`/`ReleaseWatcherLeaseIfMatches`, while lease health is consumed only by the home's own dispatch gate (`IsWatcherLeaseHealthy`, `dispatch_degraded.go`); it is never read across homes. The General health-observes each Captain as typed status: `checkAliveWithProbe` uses projection task-meta plus pane/agent probing and does not read watcher-beat state; watcher status is observed separately by converge and `RecoverTransaction`'s watcher-ensure step. Running recovery has multiple entry points, including General-scoped `RecoverTransaction`, the CLI/session `fleet.Recover` sweep, and converge's strict-dead-only relaunch path. §5 is superseded to describe that running model rather than the unbuilt lease-relay, and ADR-0008 §4's reciprocal "canonical control/Uplink interface" recovery clause now carries the matching supersession marker. (A separate §4 mechanism note — the "renewable generation and fencing token" lease design, which `WatcherLease` does not implement — is a pre-existing unbuilt-design mismatch outside this reconciliation and is not a tracked roadmap item.)
